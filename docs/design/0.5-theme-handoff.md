# Domain checkout theme handoff

Targets Paymenter 1.5.9. Implement these changes in the custom theme. The extension ZIP does not ship a theme or patch core. Stock `themes/default/views/cart.blade.php` renders product and configurable options, but does not display `checkout_config.domain` or provide a hosting upsell hook.

## Fields and links

- CartItem: `checkout_config['domain']` is the canonical full name; `plan.billing_period` is the purchased years. Product settings `enom_catalogue=1`, `enom_tld_id`, `enom_action=register|transfer` identify registrar items. Do not identify them solely by the category slug or a `domain` field.
- Checkout links: `route('products.checkout', ['category'=>$product->category, 'product'=>$product, 'plan'=>$pricedPlan->id, 'config'=>['domain'=>$domain]])`. Keep a currently priced plan in every registrar link. Native `checkoutConfig` uses the query parameter `config`.
- After checkout, Service `label` is the domain. Service plan and price represent **annual renewal**, while the initial Operation `term` and `policy.checkout_years` retain the purchased years. Initial invoice descriptions already state the purchased term. Never infer initial years from the Service plan.
- Transfer progress: resolve the extension Domain by the owned Service ID and link to `route('enom.domains.show', $domain->id).'#transfer-code'` from invoice and Service pages. Do not link to or read encrypted code/contact payloads. The extension Service include already links pending transfers to this anchor.
- Extension domain view includes `enom::partials.registration-setup` and `enom::partials.transfer-code`, each receiving the owned `$domain` model. Keep these forms on the domain page. They provide account recovery, code submission and deadline/refund wording.

## Cart display and hosting offer

Render the escaped canonical domain prominently on each registrar cart row, followed by `Registration · 3 years` or `Transfer · adds 1 year`. Keep amount due today separate from renewal. Product descriptions include `Renews at $X/yr`; display that description rather than parsing it for a number. An unavailable one-year registration price must never appear as `$0/yr`. There is no extra public renewal-price helper in the extension.

Find registrar lines with no hosting line for the same canonical domain. Identify hosting through the configured hosting server-extension names; a registrar item also has a domain field. Show one offer for the most recently added qualifying domain. Use at most three visible, currently priced hosting products in catalogue order from the theme's configured hosting category. An empty category or no priced plans hides the offer.

Use **Add hosting for example.com**, **Add**, and **Not now**. Hosting links use the checkout URL above with that hosting product, an available plan and `config[domain]` prefilled. The customer can edit it. For registration say the configured hosting DNS will be applied after registration only when that setup is actually configured. For transfers explain that the customer will need to point the name to hosting afterwards.

Dismiss per domain in session storage. Another domain may show its own offer. Without JavaScript, hide the dismiss control. Use a labelled section, one link per plan card, a real dismiss button and a defined next focus target after dismissal. Use compact rows on small screens.

## Checkout and invoice

The native checkout already supports hidden direct links, `plan`, `config`, and extension checkout fields. Rename the registrar plan panel **Registration term** and the fields panel **Domain details**. Use a fieldset and legend for term radios. With more than five terms, initially show available 1, 2, 3, 5 and 10-year plans plus the selected plan; expose the rest with an accessible **More terms** button. Show totals and per-year amounts without inventing unavailable prices. Name-specific admission errors remain authoritative.

Native checkout lands on the invoice. Add **Enter your transfer code** beside each transfer line, even while unpaid. The code can be saved before payment; submission requires both funding and a valid code. Keep the link after payment while the Domain is pending. No dashboard card is required.

## Acceptance screens

Capture desktop and mobile: hidden three-year checkout with prefilled name; two domain lines plus matching hosting; hosting offer with add/dismiss; invoice with two domain lines and transfer-code link; annual Service price after a multi-year purchase; unpaid and paid missing-code transfers; account-details hold and explicit resume; code deadline refund. Check keyboard focus, reduced motion and escaped names.

No browser verification or custom-theme implementation is part of the extension tests. Theme completion is required before claiming the hosting offer or cart-domain display is delivered.
